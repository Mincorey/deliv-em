# Contributing Documentation

Руководство для тех, кто добавляет новую документацию в проект.

## 📁 Структура

Все документы хранятся в папке `docs/`:

```
docs/
├── README.md                              ← Индекс всей документации
├── CONTRIBUTING.md                        ← Вы здесь (правила добавления)
├── ПОЛНЫЙ_АУДИТ_ПРОЕКТА_DELIV-EM.md     ← Аудит проекта
├── INFRASTRUCTURE_SETUP.md                ← Email, Rate Limit, Logging, Sentry
├── AUDIT_LOG_GUIDE.md                    ← Аудит логирование (детально)
└── AUDIT_DEPLOYMENT_CHECKLIST.md         ← Deployment чек-лист
```

## ➕ Как добавить новую документацию

### 1. Создать файл в `docs/`

```bash
touch docs/MY_NEW_FEATURE.md
```

### 2. Писать с соблюдением формата

**Используй эту структуру:**

```markdown
# 📚 Feature Name

Brief description of what this document covers.

## 🎯 Quick Start

Step-by-step getting started guide.

## 📋 Detailed Guide

Comprehensive explanation with examples.

## 💻 Code Examples

```typescript
// Actual code examples
```

## 🔧 Configuration

Environment variables and setup.

## ⚠️ Important Notes

Things to watch out for.

## 📞 Troubleshooting

Common issues and solutions.
```

### 3. Обновить `docs/README.md`

Добавь ссылку на новый документ в **docs/README.md**:

```markdown
## 📋 Содержание

### 🆕 Новая секция
- **[MY_NEW_FEATURE.md](./MY_NEW_FEATURE.md)** — Краткое описание
```

### 4. Обновить главный `README.md`

Если документация **критична для всех**, добавь в главный `README.md`:

```markdown
## 📚 Documentation

- 📋 [**My Feature**](./docs/MY_NEW_FEATURE.md) — Brief description
```

## ✍️ Writing Guidelines

### Язык

- **Основной язык:** Русский с английскими примерами кода
- **Комментарии в коде:** На русском в начале, потом на английском для production

```typescript
// Получить историю платежей
// Get payment history
const history = await getPaymentHistory(userId)
```

### Форматирование

- **Заголовки:** Используй emoji + текст
  - `# 📚 Заголовок H1`
  - `## 🎯 Заголовок H2`
  - `### 💻 Заголовок H3`

- **Блоки важной информации:**
  ```markdown
  ✅ Правильно
  ❌ Неправильно
  ⚠️ Осторожно
  💡 Совет
  🔴 КРИТИЧНО
  ```

- **Код:**
  ```markdown
  TypeScript: \`\`\`typescript
  SQL: \`\`\`sql
  Bash: \`\`\`bash
  ```

### Структура документа

1. **Краткое описание** (1-2 предложения)
2. **Быстрый старт** (5-10 минут)
3. **Подробное руководство** (20-30 минут)
4. **Примеры кода** (работающие примеры)
5. **Конфигурация** (переменные окружения и т.д.)
6. **Troubleshooting** (часто встречающиеся проблемы)

## 📝 Примеры хорошей документации

### ✅ AUDIT_LOG_GUIDE.md
- Имеет четкую структуру
- Много примеров кода
- Используется emoji для навигации
- Есть troubleshooting секция

### ✅ INFRASTRUCTURE_SETUP.md
- Разделены разные сервисы
- Есть локальное тестирование
- Чек-лист для production
- Таблицы для сравнения

## 🚫 Что НЕ нужно

- ❌ Пустые документы (пиши только если есть информация)
- ❌ Дублирование информации (ссылайся на другие документы)
- ❌ Устаревшую информацию (обновляй когда меняется код)
- ❌ Очень длинные документы (разбей на несколько)
- ❌ Много внутренних мыслей (используй только факты)

## 🔄 Обновление документации

**Когда обновлять:**
- ✅ Изменился код/конфигурация → Обнови документ
- ✅ Добавилась новая фича → Добавь документ
- ✅ Исправилась ошибка → Обнови примеры
- ✅ Найден баг в документе → Исправь сразу

**Как обновлять:**
1. Отредактируй файл в `docs/`
2. Обнови дату в конце файла
3. Создай commit с сообщением: `docs: update feature_name`

## 📋 Чек-лист перед публикацией

- [ ] Файл находится в `docs/` папке
- [ ] Имя файла в snake_case (например: `my_feature.md`)
- [ ] Добавлена ссылка в `docs/README.md`
- [ ] Если критично — добавлена ссылка в главный `README.md`
- [ ] Все примеры кода рабочие
- [ ] Нет ошибок правописания
- [ ] Используются правильные emoji
- [ ] Есть дата последнего обновления в конце

## 💡 Советы

**Делай документацию полезной:**
- Пиши для тех, кто ВПЕРВЫЕ видит эту фичу
- Показывай реальные примеры из проекта
- Объясняй ЗАЧЕМ это нужно, а не только КАК делать
- Добавляй ссылки на другие документы

**Структура примера кода:**

```typescript
// ❌ Плохо - просто код без объяснения
const result = getAuditLog()

// ✅ Хорошо - объяснение + код + результат
// Получить последние 50 логов
const { data: logs } = await getAuditLog({ limit: 50 })

// Результат:
// [
//   { operation: 'INSERT', table_name: 'transactions', ... },
//   { operation: 'UPDATE', table_name: 'ratings', ... },
// ]
```
